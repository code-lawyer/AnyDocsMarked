# 强制 GUI 流程 + 案件自动搭建（用户不建文件夹）设计（2026-08-16）

## 背景

产品目标是**agent 牵引、用户不思考复杂步骤**，release 是给 agent 读取并使用的。两处现状与该目标冲突：

1. **SKILL 第一步给了 agent「GUI 或 无头 CLI」二选一，且只把 GUI 标为"推荐"。** agent 天性偏自主无头，大概率自己跑 `ingest.py`，用户**从头到尾看不到 GUI**——本地/云端选择、token 申请链接、进度条全落空。"开不开 GUI"仍是 agent 的 prose 判断。
2. **`原始资料/` 要用户手工建并把文件放进去**——这是让用户思考的步骤。

本 spec 定两条修正 + 一条安全约束。承接 `2026-08-15-tool-vs-llm-architecture-and-ingest-orchestrator-design.md`（引擎/双前端/门禁不变）。

## 决策一 · GUI 是唯一被认可的摄入入口

- **SKILL 第一步删掉「无头自动 CLI」选项**，只留一条：agent **后台启动 GUI**、交用户操作。无头 `ingest.py` 作为引擎仍存在（GUI 底层调它、CI/无桌面兜底用），但**不再作为给 agent 的 sanctioned 用户流程路径**。
- **交接协议**（写进 SKILL，让照做的 agent 不会卡死）：agent 用**后台方式**启动 GUI（避免前台被 tkinter mainloop 阻塞）→ 告诉用户「窗口已打开，请在里面选 OCR 方式并等它跑完」→ **以 `<case>/ingest-report.json` 出现 + GUI 进程退出为完成信号** → 读 report → 才进第二部分（建 wiki、交叉验证问答）。
- **诚实边界**：prose 强制不了 agent 一定照做；但「删掉无头选项 + GUI 做成唯一入口 + 补后台启动/等 report 协议」是能拿到的最强杠杆。不追求硬保证。

## 决策二 · 无桌面环境：明确报错，绝不静默无头

`ingest_gui.py` 的 `main()` 捕获"无显示器"（`tkinter.TclError` / `no display`）→ 打印明确中文提示「本流程需在有桌面的用户电脑上运行；当前环境无图形界面」→ 以**专门的退出码**退出，让 agent 能如实转告用户。**绝不**在无桌面时自动降级去无头跑（那会让用户永远看不到窗口而不自知）。

## 决策三 · 案件自动搭建：用户给路径，系统建 `原始资料/` 并归入（移动）

用户只对 agent 说"某路径下有要处理的资料"。**该路径即 case 根**，系统负责搭结构，用户不碰文件夹名。

### 语义
- 引擎/GUI 接受一个 `<case_path>` = 用户给的文件夹。`原始资料/`、`_md/`、`.rag/`、`wiki/` 全在其下（**保留 lawiki 现有"`原始资料/` 在 case 根内"的约定不变**，只是改由系统自动填充）。
- 新增确定性首阶段 `_setup_case(case)`，在 `init_case` 之前跑：
  - 若 `原始资料/` **不存在** → 创建它，把 case 根下**所有非保留条目**（文件与子目录，保留其相对结构）**移动**进 `原始资料/`。
  - 若 `原始资料/` **已存在** → **跳过**（幂等；不重移、不追加）。

### 三条安全硬约束（移动是破坏性操作，必须守）
1. **只移动非脚手架条目**：保留名单**绝不移动**——`原始资料`、`_md`、`.rag`、`wiki`、`AGENTS.md`、`CLAUDE.md`、`ingest-report.json`、`report.json`、以及以 `.` 开头的隐藏项（如 `.git`）。其余顶层条目移入 `原始资料/`。
2. **可恢复的幂等**：`原始资料/` 已存在时不再无脑跳过，而是把仍散落在 case 根下的可移动项继续归入（同名已在里面的不覆盖）——防 Windows 下移动中途因文件被占用而部分失败、此后再也无法续传；没有散落项时才无操作。
3. **透明 + 确认**：GUI 首屏在移动前**预览**——展示 `<case_path>` 与"将把 N 项归入 `原始资料/` 再处理"，**用户点确认才执行**。移动清单记入 `ingest-report.json` 的 `stages.setup.moved`，事后可查。防"指错到 Downloads 把整盘搬走"的footgun。

### 位置
`_setup_case` 放在引擎（`ingest.py`）作为首阶段，GUI 与内部 CLI 都经它——单一来源。GUI 首屏的"预览计数"是显示用途的轻量扫描（best-effort），真正的移动由引擎执行。

## 部署形态（收束）

```
用户对 agent 说：D:\某路径 下有资料
        │
        ▼
agent（唯一动作）：后台启动 GUI，传入该路径
        │
        ▼
GUI：① 预览「将把 N 项归入 原始资料/」→ 用户确认
     ② 图形化选 本地/云端（+ token + consent）
     ③ 进度条跑摄入（引擎：_setup_case→init_case→convert→index→reconcile→门）
     ④ 完成弹窗 + 产出 ingest-report.json
        │
        ▼（report 出现 + GUI 退出）
agent：读 report → 建 wiki（LLM）→ 交叉验证问答
```
用户全程只面对：一段对话（给路径）+ 一个窗口（选择/看进度）。不建文件夹、不选无头、不碰步骤。

## 非目标

- 不改 lawiki 内部"`原始资料/` 在 case 根、`_md/<rel>` 锚点"的路径契约——只自动填充 `原始资料/`。
- 不做"复制"或"只读引用"模式（用户已选"移动进 case 根内"）。
- 不支持多个原始来源路径合并（一个 case 一个源路径）。
- 不追求 GUI 强制的硬保证（prose 边界，见决策一）。
- 不动引擎的门禁/退出码/report 契约、不动 makeitdown/rag/lawiki 本体。

## 验收

- `_setup_case`（纯 IO，可单测）：合成 case 根含散落文件+子目录 → 跑后文件在 `原始资料/` 下、保留名单未动、结构保留；`原始资料/` 已存在 → 幂等无操作；隐藏项/保留项不被移。
- 无桌面：`main()` 在 `tk.Tk()` 抛 `TclError` 时打印提示 + 专用退出码（mock `tkinter.Tk` 抛错可测）。
- SKILL 第一步：无「无头 CLI」sanctioned 选项；含后台启动 + `ingest-report.json` 交接协议；第〇/第三步及铁律不变。
- GUI 首屏移动预览 + 确认（手工冒烟：正常路径 / 指到大文件夹时的确认拦截）。
- 三模块全量测试 + ruff `E9,F` 不受影响。
